### Направление 2 — Межбиржевой арбитраж (новое, по APM)

**Суть:** мониторить спред одной пары (BTC/USDT, ETH/USDT, SOL/USDT) между Binance и Bybit. При спреде ≥ 0.40% — одновременно покупать на дешёвой и продавать на дорогой.

**Почему это работает:** задержка трансфера между биржами (минуты) создаёт окно которое HFT боты не могут закрыть физически.

**Целевая прибыль:** $1.00–2.50 за сделку при позиции $500–1000.

#### Фазы арбитража

**Фаза 0 — Только мониторинг (без сделок)**
- Подключить WebSocket к Binance Depth Stream + Bybit orderbook
- Логировать все спреды ≥ 0.30% с timestamp
- Длительность: **60 дней** (быстрый трек) или **180 дней** (точный трек)
- Критерий перехода: ≥ 15 сигналов/день со спредом ≥ 0.40%

**Фаза 1 — Paper trading**
- Симулировать сделки на живом стакане без реального капитала
- Использовать TopLevelFillModel: учитывать slippage, задержку между ногами, комиссии
- Критерий перехода: ≥ 50 виртуальных сделок, net_profit > 0 с учётом комиссий

**Фаза 2 — Tier-1 (минимальный капитал)**
- $300 на Binance + $300 на Bybit (pre-funded, без трансферов)
- Ребалансировка через USDT-TRC20 (~$1/перевод)
- Критерий перехода: 30 реальных сделок, WR ≥ 55%

**Фаза 3 — Tier-2 (полноценная работа)**
- $1000–3000 на каждой бирже
- Подключить OKX как третью биржу

## Архитектура (целевая)

```
traderbot/
├── analyst/            # Данные: funding rate, OHLCV, OI (Bybit)
├── executor/           # Исполнение ордеров (Bybit)
├── gate/               # Alpha Gate v2 (фильтр сигналов)
├── momentum/           # Стратегия B: 5m VWAP MR ✅
├── arbitrage/          # НОВОЕ: межбиржевой арбитраж
│   ├── monitor.py      # WebSocket мониторинг спредов
│   ├── fill_model.py   # Симуляция исполнения (paper)
│   ├── executor.py     # Реальное исполнение (asyncio.gather)
│   └── rebalancer.py   # Ребалансировка через TRC20
├── risk_manager/       # Риск-менеджер (общий)
├── shared/             # Config, DB, Telegram
└── scripts/            # Бэктесты
```

## Risk Management (обязательно)

| Параметр | Значение |
|---|---|
| Макс. убыток за сделку | 2% от депозита |
| Макс. дневной убыток | 5% от депозита |
| Hard stop (дневной) | выход из всех позиций, пауза 24ч |
| Макс. размер позиции | quarter-Kelly с tail_loss_gate |
| Асимметричное исполнение ног | закрыть обе, зафиксировать убыток |

## Технические требования

- **Язык:** Python 3.11+
- **Биржи:** Bybit (основная), Binance (арбитраж), OKX (опционально)
- **Данные:** native WebSocket (не REST polling)
- **БД:** SQLite (dev) / PostgreSQL (prod)
- **Деплой:** Linux сервер, systemd, 24/7
- **Уведомления:** Telegram бот (сигналы, сделки, ошибки)
- **Мониторинг:** логи через loguru, ежедневный отчёт в Telegram
